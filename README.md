# Queue

Система управления электронной очередью для Ubuntu Server 24.04 LTS.

Для входа откройте адрес сервера в браузере. Терминал доступен по пути
`/terminal.html`, табло с видео – по пути `/board.html?screen=media`.
Страницы и оформление сайта находятся в папке `web`.

## Установка и обновления через меню

Поддерживается Ubuntu Server 24.04 LTS на x86-64. На сервере нужен доступ
к GitHub, PyPI и источникам системных пакетов.

На чистом сервере скачайте установщик и запустите его:

```bash
curl --fail --location --output qronion-setup.sh \
  https://raw.githubusercontent.com/eulerformula69/electronicqueue/main/deploy/setup.sh
sudo bash qronion-setup.sh
```

В меню выберите «Установить». Укажите IPv4 сервера или нажмите Enter,
чтобы определить адрес автоматически. Подтвердите установку.
Если команда `curl` отсутствует, установите её: `sudo apt-get update && sudo apt-get install -y curl`.

Если папка проекта уже находится на сервере, скачивание не требуется:

```bash
sudo bash deploy/menu.sh
```

Установщик настраивает PostgreSQL, приложение, Nginx, HTTP, HTTPS и Grafana.
Приложение размещается в `/home/qronion`.
Адреса страниц и пути к паролям и сертификату появятся в конце установки.
Пользователь, запустивший установку через `sudo`, получает доступ к папке проекта.
Пароли доступны в `~/queue-credentials.txt`, а при установке от root:
`sudo cat /root/queue-credentials.txt`.

После установки для всех операций открывайте одно меню:

```bash
sudo qronion
```

В меню доступны установка, проверка обновлений, обновление, состояние служб,
копия БД и восстановление после прерванного обновления.
Повторная установка завершённой системы через меню заблокирована: используйте обновление.
Если первая установка прервалась, исправьте указанную причину и повторите пункт «Установить».

### Где запускать `sudo qronion`

Команду выполняют в терминале сервера Ubuntu: непосредственно на сервере
или после подключения к нему по SSH. В PowerShell на Windows сначала
подключитесь к серверу, затем откройте меню:

```text
ssh пользователь@IP_сервера
sudo qronion
```

Замените `пользователь` и `IP_сервера` своими значениями.
Для интерактивного меню нужен обычный терминал. Не передавайте установщик
через `curl | bash` и не запускайте меню через перенаправленный ввод.

`sudo` даёт права администратора для установки компонентов и управления
службами. При запросе введите пароль своей учётной записи на сервере.
Ввод пароля в терминале не отображается.

`qronion` запускает меню из установленной папки проекта. Команда создаётся
установщиком в `/usr/local/bin/qronion` и работает из любой текущей папки.
Переходить в `/home/qronion` для открытия меню не требуется.
Само открытие меню ничего не устанавливает, не обновляет и не останавливает.

Введите номер пункта и нажмите Enter:

| Пункт | Действие | Подтверждение |
| --- | --- | --- |
| 1. Установить на чистую Ubuntu 24.04 | Настраивает приложение и системные компоненты | Да, после ввода IP |
| 2. Проверить обновления | Скачивает сведения и файлы для сравнения, показывает версию и число замен | Нет, установленная очередь продолжает работать |
| 3. Обновить очередь | Готовит зависимости, сохраняет БД, обновляет приложение и проверяет запуск | Да |
| 4. Проверить состояние | Показывает состояние служб, проверяет структуру БД и наличие прерванного обновления | Нет |
| 5. Создать резервную копию БД | Сразу создаёт отдельный дамп PostgreSQL | Нет |
| 6. Восстановить после прерванного обновления | Завершает восстановление по сохранённому шагу операции | Да, возможна замена БД копией |
| 7. Восстановить БД из копии | Предлагает выбрать файл из `/var/backups/queue/db/` и заменить текущую базу | Введите `yes` после проверки имени файла |
| 0. Выйти | Закрывает меню, очередь продолжает работать в текущем состоянии | Нет |

Для подтверждения введите `д` или `y` и нажмите Enter. Пустой ответ отменяет
действие. После операции нажмите Enter, чтобы вернуться в меню.
Выход из меню не останавливает службу очереди.

### Где хранятся приложение и данные

Новая установка размещает очередь в `/home/qronion`. Если очередь уже установлена
в `/home/queue/queue_project`, меню и обновлятор продолжают использовать этот каталог.
В командах ниже для такой установки подставьте прежний путь.
Папка, из которой запустили установщик, не определяет место установки.
Меню не предлагает выбирать другой каталог.

Пути относительно каталога установки:

| Путь | Содержимое |
| --- | --- |
| `app/`, `main.py` | Серверная часть приложения |
| `queue/` | Веб-интерфейс, медиафайлы и файлы синтеза речи |
| `main.env` | Настройки сервера, включая адрес подключения к БД |
| `venv/` | Python-окружение приложения. После управляемого обновления это ссылка на окружение в `/home/qronion/.environments/` |
| `queue/media/` | Загруженные медиафайлы |
| `queue/tts/` | Модель речи и кэш сгенерированных фраз |
| `data/map.json` | Локальная карта |
| `data/docs/` | Загруженные документы |
| `deploy/` | Установщик, меню, обновление и резервное копирование |
| `release.json` | Версия успешно установленного релиза, если источник содержит сведения Git |

База `queue` хранится в PostgreSQL отдельно от папки приложения.
Пользователь службы приложения: `queue`, служба: `queue.service`.
Точный каталог данных PostgreSQL можно посмотреть на сервере:

```bash
sudo -u postgres psql -Atc 'SHOW data_directory;'
```

Другие пути на сервере:

| Путь | Содержимое |
| --- | --- |
| `/var/backups/queue/db/` | Обычные дампы, в том числе из пункта 5 меню |
| `/var/lib/queue-update/<идентификатор>/` | Копии изменяемых файлов и БД перед конкретным обновлением |
| `/var/lib/queue-update/pending.json` | Сохранённый шаг незавершённого обновления |
| `/var/backups/queue-install/` | Копии отдельных настроек, созданные установщиком |
| `/root/queue-credentials.txt` | Учётные данные, созданные установщиком |
| `~/queue-credentials.txt` | Копия учётных данных для пользователя, запустившего установку через `sudo` |
| `~/queue-rootCA.pem` | Корневой сертификат для установки на клиентские устройства при запуске установщика через `sudo` |
| `/root/queue-rootCA.pem` | Экспорт корневого сертификата на сервере |

Папка PostgreSQL не входит в `/home/qronion`.
Копирование одной папки приложения не создаёт резервную копию работающей БД.

### Как работает обновление

Пункт «Проверить обновления» показывает версию и число изменённых файлов.
Он не останавливает очередь и не меняет установленное приложение.
Обновления берутся из ветки `main` этого репозитория.

Пункт «Обновить очередь» после подтверждения выполняет пять шагов:

1. Готовит отдельное Python-окружение с закреплёнными зависимостями. Очередь ещё работает.
2. Останавливает очередь и создаёт копию БД.
3. Заменяет файлы приложения и подключает подготовленное окружение.
4. Применяет миграции и проверяет структуру БД.
5. Запускает очередь и проверяет ответ страницы входа.

Версия релиза записывается после успешной проверки запуска. Повторное обновление
той же версии без изменений ничего не переустанавливает.
Настройки `main.env`, медиафайлы, модель речи, карта и документы сохраняются.
Локальные исключения из `deploy/exclude_from_update.txt` также сохраняются.
Обновление не удаляет отсутствующие в новой версии файлы и не меняет системные
пакеты, настройки Nginx, сертификаты или установленную Grafana.

Копии изменённых файлов и БД находятся в `/var/lib/queue-update/<идентификатор>/`.
Они сохраняются после обновления и не удаляются автоматически.
Это копия для отката обновления, а не полный архив сервера: медиа, документы
и настройки требуют отдельного резервного копирования.

### Если обновление прервалось

При ошибке подготовки зависимостей очередь продолжает работать.
При ошибке после остановки очередь остаётся остановленной, а шаг операции
сохраняется в `/var/lib/queue-update/pending.json`.
Следующее обновление заблокировано до восстановления.

Откройте `sudo qronion`, выберите «Восстановить после прерванного обновления»
и подтвердите действие. Возвращаются прежние файлы и Python-окружение.
Если миграция могла начаться, восстанавливается и БД из копии перед обновлением.
После проверки структуры БД и ответа приложения очередь снова работает.
Восстановление после собственной ошибки можно запустить повторно.

Восстановление возвращает БД к моменту перед обновлением. Изменения, которые
успели появиться после запуска новой версии, будут потеряны.
Не запускайте службу вручную, пока восстановление не завершилось.

### Если команда `qronion` не найдена

Команда появляется после новой установки или успешного перехода на управляемое
обновление. На старом сервере её может ещё не быть.

Если новое меню уже находится в установленной папке, откройте его напрямую:

```bash
sudo bash /home/qronion/deploy/menu.sh
```

Для существующей установки с миграциями Alembic, в которой ещё нет нового меню, перенесите
свежую папку проекта на сервер. Сначала запустите управляемое обновление из неё:

```bash
sudo python3 deploy/linux_update.py
```

После успешного обновления откройте меню командой `sudo qronion`.
Короткие команды создаются и при переходе со старой установки. При прерывании
первого перехода восстановление запускается из свежей папки проекта:
`sudo python3 deploy/linux_update.py --recover`.

Базы старых версий без Alembic не переносятся этим обновлением автоматически.
Для них запланирована чистая установка с пустой базой, см.
[правила миграций](docs/DATABASE_MIGRATIONS.md).

Прежний установщик доступен для обслуживания: `sudo bash deploy/install.sh`.
Он заново настраивает системные компоненты, поэтому для обычного обновления
приложения используйте меню.

## HTTPS

Установщик создаёт локальный центр сертификации `mkcert`, выпускает сертификат для IP сервера и одновременно оставляет доступными HTTP и HTTPS без перенаправления.

Корневой сертификат автоматически копируется в домашний каталог пользователя, запустившего установку:

```text
~/queue-rootCA.pem
```

В конце установки выводится готовая команда для любого Windows-компьютера. Имя пользователя и IP текущей ВМ подставляются автоматически:

```powershell
scp <пользователь_ВМ>@<IP_ВМ>:<домашняя_папка>/queue-rootCA.pem .\queue-rootCA.pem
```

На Windows сертификат устанавливается из PowerShell администратора:

```powershell
certutil -addstore -f Root "C:\путь\к\queue-rootCA.pem"
```

На Raspberry Pi или другом Linux:

```bash
sudo cp queue-rootCA.pem /usr/local/share/ca-certificates/queue-mkcert.crt
sudo update-ca-certificates
```

После установки сертификата браузер необходимо полностью перезапустить. Файл `rootCA-key.pem` с сервера переносить нельзя.

## Обновление дашборда Grafana

После экспорта дашборда из Grafana нормализуйте JSON перед добавлением в Git:

```bash
python scripts/normalizeGrafanaDashboard.py \
    ~/Downloads/export.json \
    data/statistics.json

git diff -- data/statistics.json
```

Для перезаписи входного файла второй путь можно не указывать. В репозиторий должен
попадать только нормализованный `data/statistics.json`: инструмент удаляет локальные
идентификаторы экспорта и привязывает PostgreSQL к стабильному `queue-postgres`.

Старый файловый обновлятор также находится в рабочем проекте. Он не выполняет
зависимости, миграции и проверку запуска. Для обычного обновления используйте
`sudo qronion`. Следующие команды предназначены для ручного обслуживания:

```bash
cd /home/qronion
./deploy/update_from_git.py --repo https://github.com/USER/REPOSITORY.git
./deploy/update_from_git.py --repo https://github.com/USER/REPOSITORY.git --apply
```

Первая команда только показывает будущие изменения, вторая применяет их с резервной копией файлов проекта.

## Резервное копирование базы данных

Дампы сохраняются в `/var/backups/queue/db/` в формате PostgreSQL custom (`queue_YYYYMMDD_HHMMSS.dump`).

### Можно ли сразу запустить `sudo queue-backup`?

**Нет, не с этого компьютера (Windows).** Команды выполняются **на сервере Ubuntu**, где уже стоит очередь — по SSH.

**На сервере тоже не сразу**, пока туда не попадут новые скрипты из этого репозитория. Порядок такой:

1. Здесь (на ПК с кодом): закоммитить и отправить изменения в Git.
2. Зайти на сервер по SSH под пользователем, у которого есть доступ к проекту.
3. Обновить файлы на сервере через `update_from_git.py --apply`.
4. После этого запускать бэкап.

Все команды ниже — **на сервере**, из каталога проекта:

```bash
cd /home/qronion
```

### Первый раз: подготовка на сервере

```bash
# 1. Посмотреть, что изменится (без применения)
./deploy/update_from_git.py --repo https://github.com/USER/REPOSITORY.git

# 2. Применить обновление (скачает deploy/backup_db.sh и deploy/restore_db.sh)
./deploy/update_from_git.py --repo https://github.com/USER/REPOSITORY.git --apply

# 3. Создать каталог для дампов (если install.sh после этого не запускали)
sudo install -d -m 0770 -o root -g queue /var/backups/queue/db

# 4. Проверочный бэкап — работает сразу, без queue-backup
sudo bash /home/qronion/deploy/backup_db.sh
```

Чтобы появились короткие команды `queue-backup` и `queue-restore`, один раз перезапустите установщик (данные и `main.env` сохранятся):

```bash
cd /home/qronion
sudo bash deploy/install.sh
```

После `install.sh` можно использовать `sudo queue-backup` вместо полного пути к скрипту.

### Обычные команды (sudo, на сервере)

Закрыть рабочий день сразу:

```bash
sudo queue-close-day --finish-tickets --operator-offline
```

Без флагов команда только показывает подсказку. Для запуска нужно явно выбрать:

- `--finish-tickets` — завершить обслуживаемые билеты, а ожидающие и
  отложенные отменить; либо `--cancel-tickets` — отменить все открытые билеты;
- `--operator-offline` — перевести операторов в офлайн и закрыть их сессии;
- `--operator-online` — не менять статусы и сессии операторов;
- `--operator-break` — перевести операторов в перерыв, сохранив их сессии.

Запланировать несколько одноразовых закрытий в интерактивном режиме:

```bash
sudo queue-close-day --finish-tickets --operator-offline --schedule
```

Если короткая команда не установлена, скрипт можно запустить напрямую тем
Python, которым он обычно запускается на сервере:

```bash
python3 scripts/closeDay.py --finish-tickets --operator-offline --schedule
```

На Windows:

```bat
py scripts/closeDay.py --finish-tickets --operator-offline --schedule
```

Скрипт остаётся запущенным и проверяет время внутри процесса. До последнего
закрытия окно терминала нельзя закрывать, а компьютер нельзя выключать или
переводить в спящий режим. Остановить таймер можно сочетанием `Ctrl+C`.

Введите даты по одной строке, например `24.07.2026 18:00` и
`25.07.2026 14:00`, затем нажмите Enter на пустой строке. Укажите местное время очереди. Пояс задаёт параметр `QUEUE_TIMEZONE` в `main.env`.
Каждое задание выполняется один раз.

Те же даты можно передать одной командой без диалога:

```bash
sudo queue-close-day \
  --finish-tickets \
  --operator-offline \
  --schedule "24.07.2026 18:00" \
  --schedule "25.07.2026 14:00"
```

Ручной бэкап:

```bash
sudo queue-backup
```

Или без обёртки (если `queue-backup` ещё не установлен):

```bash
sudo bash /home/qronion/deploy/backup_db.sh
```

Дополнительные варианты:

```bash
sudo queue-backup --keep-days 30
sudo queue-backup --label before_update
```

Ежедневный автоматический бэкап в 03:15:

```bash
sudo queue-backup --install-cron
```

Журнал cron: `/var/log/queue-db-backup.log`.

Список дампов:

```bash
ls -lh /var/backups/queue/db/
```

### Восстановление из дампа

В меню `sudo qronion` выберите пункт 7 и введите номер нужной копии.
Чтобы вернуться без восстановления, введите `0` при выборе файла.
После подтверждения скрипт сохранит текущую БД, восстановит выбранную копию
и проверит структуру базы. Если очередь работала, скрипт снова запустит её
после успешной проверки.

Если служба `queue` работала, скрипт остановит её и запустит после успешной проверки структуры базы. При ошибке после остановки служба останется выключенной. После устранения причины повторите восстановление и запустите службу командой `sudo systemctl start queue`. Перед восстановлением автоматически создаётся страховочный дамп с меткой `before_restore`.

```bash
sudo queue-restore /var/backups/queue/db/queue_20250624_031500.dump
```

Последний дамп в каталоге (кроме страховочных копий перед восстановлением):

```bash
sudo queue-restore latest
```

Без вопроса «Продолжить?» (осторожно):

```bash
sudo queue-restore /var/backups/queue/db/queue_20250624_031500.dump -y
```

Через полный путь к скрипту:

```bash
sudo bash /home/qronion/deploy/restore_db.sh /var/backups/queue/db/queue_20250624_031500.dump
```

Проверка, что восстановление вообще работает (на уже сделанном тестовом дампе):

```bash
sudo queue-backup --label test_copy
sudo queue-restore /var/backups/queue/db/queue_YYYYMMDD_HHMMSS_test_copy.dump -y
```

## Учётные записи

Список администраторов и терминалов:

```bash
sudo queue-admin show
```

Создание администратора или терминала (пароль запрашивается скрыто):

```bash
sudo queue-admin add new_admin admin
sudo queue-admin add new_terminal terminal
```

Смена пароля и удаление записи:

```bash
sudo queue-admin change new_admin --password
sudo queue-admin delete new_admin
```
